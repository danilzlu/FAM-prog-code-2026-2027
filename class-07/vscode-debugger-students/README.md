# Отладка программ на C в VS Code

В папке `.vscode` находятся готовые `tasks.json` (сборка) и `launch.json` (запуск отладчика). Они предназначены для **программ из одного `.c`-файла**.

## Подготовка

1. Установите VS Code.
2. Установите расширение:
   - **macOS:** CodeLLDB (`vadimcn.vscode-lldb`);
   - **Linux и Windows:** C/C++ (`ms-vscode.cpptools`).
3. Откройте в VS Code **папку**, содержащую `.vscode`, через **File → Open Folder**. Не открывайте только отдельный `.c`-файл.
4. Откройте нужный `.c`-файл в редакторе, поставьте breakpoint щелчком слева от номера строки.
5. Перейдите в **Run and Debug**, выберите конфигурацию своей ОС и нажмите **F5**.

При F5 VS Code сначала компилирует **текущий открытый файл** с `-g -O0`, затем запускает отладчик. Исполняемый файл создаётся рядом с исходником (на Windows — `.exe`).

## macOS

Используется Apple Clang из Xcode Command Line Tools и расширение CodeLLDB.

Проверьте в терминале:

```bash
clang --version
```

Если компилятора нет, выполните `xcode-select --install`.

Выберите **macOS — Clang + LLDB**.

## Windows (основная инструкция курса)

Мы используем **WinLibs standalone MinGW-w64**: 64-битную сборку **x86_64, UCRT, POSIX threads** (ZIP без LLVM/Clang/LLD/LLDB).

Распакуйте архив так, чтобы существовали файлы:

```text
C:\winlibs\mingw64\bin\gcc.exe
C:\winlibs\mingw64\bin\gdb.exe
```

Добавьте `C:\winlibs\mingw64\bin` в пользовательскую переменную **Path**, перезапустите VS Code и проверьте в PowerShell:

```powershell
gcc --version
gdb --version
```

Выберите **Windows — WinLibs GCC + GDB**.

**Важно:** если вы распаковали WinLibs в другое место, измените путь `command` в `.vscode/tasks.json` и `miDebuggerPath` в `.vscode/launch.json`. Не выбирайте автоматически созданную VS Code задачу `C/C++: gcc.exe build active file`, если она указывает на другой компилятор.

## Linux

Установите GCC и GDB, например на Ubuntu/Debian:

```bash
sudo apt update
sudo apt install build-essential gdb
```

Проверьте `gcc --version` и `gdb --version`. Выберите **Linux — GCC + GDB (включая WSL)**.

## Windows с WSL (необязательный вариант)

Если вы используете WSL, установите GCC и GDB **внутри Linux**, откройте проект в VS Code через **WSL: Open Folder in WSL** (расширение WSL) и выберите конфигурацию **Linux — GCC + GDB (включая WSL)**. В обычном Windows-окне VS Code эта конфигурация не предназначена для запуска.

## Основные команды отладчика

| Команда | Назначение |
|---|---|
| F5 | Продолжить выполнение |
| F9 | Установить/снять breakpoint |
| F10 | Step Over: выполнить строку, не заходя внутрь функции |
| F11 | Step Into: войти в вызываемую функцию |
| Shift+F11 | Step Out: выйти из текущей функции |
| Shift+F5 | Остановить отладку |

Панели **Variables**, **Watch** и **Call Stack** позволяют наблюдать значения переменных, выражения и стек вызовов.

## Частые ошибки

- **Запускается Windows-компилятор на macOS:** выбрана неверная задача или конфигурация. Выберите конфигурацию macOS, не используйте `C/C++: gcc.exe build active file`.
- **`gdb.exe` не найден на Windows:** проверьте расположение WinLibs и путь `C:\winlibs\mingw64\bin`.
- **Не останавливается на breakpoint:** убедитесь, что запускается только что собранный исполняемый файл, а сборка содержит `-g -O0`.
- **`preLaunchTask` не найден:** файлы `.vscode/launch.json` и `.vscode/tasks.json` должны лежать в одной открытой папке проекта.
- **Несколько `.c`-файлов:** эти шаблоны компилируют только активный файл. Для многофайловых проектов используйте Makefile и отдельную задачу сборки.
- **Нет ввода с клавиатуры:** используйте встроенный терминал; если конкретная конфигурация/расширение не предоставляет интерактивный ввод, настройте запуск в терминале согласно его документации.

## Проверка перед занятием

Создайте `main.c`:

```c
#include <stdio.h>

int main(void) {
    int x = 5;
    x += 3; // поставьте breakpoint здесь
    printf("%d\n", x);
    return 0;
}
```

Запустите F5 и проверьте, что отладчик остановился на breakpoint и показывает `x`.



## Работа с отладчиком в VS Code

Отладчик (debugger) позволяет выполнять программу по шагам, останавливать её в выбранных местах и наблюдать за значениями переменных.

Это особенно полезно, когда программа компилируется, но работает неправильно: выдаёт неверный результат, зависает или аварийно завершается.

### 1. Запуск отладчика

1. Откройте исходный `.c`-файл в VS Code.
2. Откройте панель **Run and Debug** слева (значок треугольника с жуком).
3. В выпадающем списке выберите конфигурацию для своей операционной системы.
4. Нажмите **F5** или зелёный треугольник **Start Debugging**.

Программа будет скомпилирована с отладочной информацией и запущена под управлением отладчика.

**Важно:** перед нажатием F5 убедитесь, что открыт именно тот исходный файл, который вы хотите отлаживать.

### 2. Точки останова (Breakpoints)

Точка останова позволяет приостановить выполнение программы перед определённой строкой.

Чтобы поставить точку останова:

1. Найдите нужную строку кода.
2. Щёлкните мышью слева от номера строки.
3. Появится красная точка.

При запуске отладчик остановится перед выполнением этой строки.

Чтобы убрать точку останова, щёлкните по ней ещё раз.

**Попробуйте:** поставьте точку останова внутри цикла и запустите программу. При каждом повторном достижении этой строки выполнение будет останавливаться.

### 3. Основные кнопки отладчика

Во время отладки в VS Code появляется панель управления.

| Кнопка | Название | Клавиша | Действие |
|---|---|---|---|
| <icon name="play" color="success" inline/> | Continue | `F5` | Продолжить выполнение до следующей точки останова |
| <icon name="arrow-right-to-line" inline/> | Step Over | `F10` | Выполнить текущую строку, не заходя внутрь вызываемой функции |
| <icon name="arrow-down-to-line" inline/> | Step Into | `F11` | Перейти внутрь вызываемой функции |
| <icon name="arrow-up-from-line" inline/> | Step Out | `Shift + F11` | Выполнить оставшуюся часть текущей функции и вернуться в вызывающую |
| <icon name="pause" inline/> | Pause | — | Приостановить выполняющуюся программу |
| <icon name="rotate-cw" inline/> | Restart | `Ctrl + Shift + F5` | Перезапустить отладку |
| <icon name="square" color="danger" inline/> | Stop | `Shift + F5` | Завершить сеанс отладки |

На некоторых ноутбуках для клавиш `F5`, `F10`, `F11` требуется дополнительно удерживать `Fn`.

### 4. Step Over и Step Into: в чём разница?

Рассмотрим программу:

```c
#include <stdio.h>

int square(int x)
{
    int result = x * x;
    return result;
}

int main(void)
{
    int a = 5;
    int b = square(a);
    printf("%d\n", b);

    return 0;
}
```

Поставьте точку останова на строке:

```c
int b = square(a);
```

Теперь попробуйте два способа выполнения:

**Step Over (F10)**

Отладчик выполнит вызов `square(a)` целиком и остановится на следующей строке в `main`.

**Step Into (F11)**

Отладчик перейдёт внутрь функции `square`, где можно будет последовательно проследить вычисление `result`.

Если вы оказались внутри функции и хотите вернуться в `main`, используйте **Step Out (Shift + F11)**.

### 5. Просмотр значений переменных

Когда программа остановлена, откройте панель **Run and Debug**.

В разделе **Variables** отображаются доступные переменные и их текущие значения.

Например, при отладке бинарного поиска полезно следить за переменными:

```c
left
right
mid
```

После каждого шага можно увидеть, как меняются границы поиска.

Также можно навести указатель мыши на переменную непосредственно в исходном коде — VS Code покажет её значение.

### 6. Watch — наблюдение за выражениями

В разделе **Watch** можно добавить выражения, значения которых будут вычисляться при каждой остановке программы.

Нажмите `+` рядом с заголовком **Watch** и введите, например:

```c
left
right
mid
right - left
a[mid]
```

Это особенно полезно для отслеживания инвариантов алгоритма.

Например, при бинарном поиске можно наблюдать, уменьшается ли длина рассматриваемого отрезка после каждой итерации.

**Внимание:** выражения в Watch должны быть допустимы в текущем контексте выполнения. Не следует добавлять выражения с побочными эффектами, изменяющими состояние программы.

### 7. Call Stack — стек вызовов

Раздел **Call Stack** показывает, какие функции вызваны в данный момент и откуда они были вызваны.

Например:

```text
main
  └── binary_search
```

Если программа использует рекурсию, в стеке может оказаться несколько вызовов одной функции с разными аргументами.

Щёлкнув по кадру стека, можно посмотреть значения локальных переменных соответствующего вызова.

### 8. Условные точки останова

Иногда цикл выполняется тысячи раз, а ошибка возникает только на определённой итерации.

Чтобы не останавливаться каждый раз:

1. Щёлкните правой кнопкой мыши слева от номера строки.
2. Выберите **Add Conditional Breakpoint**.
3. Введите условие, например:

```c
mid == 7
```

Теперь отладчик остановится на этой строке только тогда, когда условие выполнено.

Можно также изменить существующую точку останова через контекстное меню.

### 9. Как исследовать зависшую программу

Если программа перестала отвечать:

1. Запустите её через отладчик.
2. Дождитесь зависания.
3. Нажмите **Pause**.
4. Посмотрите, на какой строке остановилось выполнение.
5. Изучите значения переменных.
6. Используйте **Step Over**, чтобы проследить несколько итераций.

Если программа попала в бесконечный цикл, часто можно обнаружить переменные, которые перестали изменяться.

Например, в бинарном поиске границы `left` и `right` могут оставаться прежними, из-за чего алгоритм никогда не завершится.

### 10. Как завершить отладку

Нажмите **Stop (Shift + F5)**.

После изменения исходного кода запустите отладчик заново через **F5**, чтобы программа была повторно скомпилирована.

Не путайте **Continue** с **Restart**: первая кнопка продолжает текущий запуск, а вторая начинает выполнение программы заново.

## Небольшое упражнение

Запустите демонстрационную программу с ошибкой бинарного поиска.

1. Убедитесь, что программа не завершается.
2. Поставьте точку останова внутри цикла.
3. Добавьте в Watch переменные `left`, `right`, `mid`.
4. Несколько раз нажмите F10.
5. Определите, почему границы поиска перестают изменяться.
6. Исправьте ошибку.
7. Запустите программу повторно и убедитесь, что она работает правильно.

**Цель упражнения — не просто исправить ошибку, а научиться находить её причину с помощью отладчика.**
