# `csvstat`: необязательный стартовый каркас

Этот проект — **не шаблон обязательной архитектуры** и не часть формальных требований лабораторной.

Его можно:

- использовать как отправную точку;
- менять как угодно;
- перестраивать модули;
- удалять ненужные файлы;
- вообще не использовать.

Идея каркаса — показать один из разумных способов начать большую программу на C, не складывая всё в `main.c`.

## Возможное разбиение

```text
src/
    main.c       точка входа и запуск нужного режима
    cli.c        разбор аргументов командной строки
    csv.c        чтение и разбор CSV
    types.c      распознавание NULL / INT / DOUBLE / STRING
    stats.c      накопление статистик
    report.c     человекочитаемый отчёт
    binary.c     бинарный режим уровня 10/10

include/
    *.h          интерфейсы соответствующих модулей
```

Это только один вариант. Например, `schema` можно выделить в отдельный модуль, а `csv.c` — разбить на чтение файла и собственно разбор полей.

## Важный архитектурный вопрос

Перед реализацией каждого модуля полезно ответить на три вопроса:

1. Что этот модуль знает?
2. Какие функции он предоставляет другим модулям?
3. Кто владеет выделенной динамической памятью и кто обязан её освобождать?

Если эти ответы трудно сформулировать, интерфейс модуля, вероятно, ещё стоит упростить.

## Сборка

Обычная:

```bash
make
```

После этого должен появиться файл:

```text
./csvstat
```

Сборка с санитайзерами:

```bash
make sanitize
```

Оптимизированная сборка для замеров уровня 10:

```bash
make release
```

Очистка:

```bash
make clean
```

## С чего начать

Разумный порядок работы может быть таким:

1. добиться корректного разбора аргументов командной строки;
2. научиться читать одну запись CSV;
3. определить представление поля и строки;
4. реализовать определение типов;
5. добавить `schema`;
6. добавить статистики;
7. затем расширять парсер до полного уровня 8;
8. после этого добавлять возможности уровней 9 и 10.

Необязательно проектировать всю программу целиком заранее. Но интерфейсы между уже появившимися модулями лучше обдумывать до того, как на них начнёт зависеть много кода.
