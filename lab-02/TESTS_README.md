# Студенческие E2E-тесты: avlset

Архив распаковывается в корень репозитория рядом с `Makefile` (файлы `run_tests.py`, `generate_tests.py`, каталог `tests/`). Требуется Python 3.9+ и GNU Make. Рекомендуемая среда для Windows — WSL/Ubuntu.

```bash
python3 run_tests.py --level 4
python3 run_tests.py --level 8 --stress
python3 run_tests.py --level 10 --stress
python3 run_tests.py --level 10 --sanitize
python3 run_tests.py --level 10 --sanitize --stress
```

По умолчанию тестировщик выполняет `make` (или `make sanitize` при флаге `--sanitize`), затем запускает `./avlset` с каждым `.in` и сравнивает stdout с соответствующим `.expected` построчно. `--no-build` отключает автоматическую сборку. `--project PATH` позволяет указать корень проекта, если скрипт запущен из другого каталога.

Для каждого теста выводятся результат, время, первая строка несовпадения или ошибка процесса/санитайзера. Лимиты времени по умолчанию: 3 с для обычных тестов и 12 с для стресс-тестов (для санитайзеров умножаются на 3). Переопределяются флагами `--timeout` и `--stress-timeout`. Это ориентиры для самостоятельной проверки, **не официальные лимиты преподавательского стенда**. Результаты зависят от мощности компьютера.

`generate_tests.py` детерминированно пересоздаёт `.in` и `.expected` с помощью независимой модели упорядоченного множества на Python. Для генерации дополнительных случаев можно менять параметры в этом файле; для обычного прогона генератор не нужен.

Файлы `L4_*`, `L6_*`, `L8_*`, `L9_*`, `L10_*` соответствуют уровням. Выбор уровня включает тесты всех более низких уровней. `stress`-тесты содержат десятки тысяч команд, включая монотонные вставки, запросы рангов, сумм и массовое удаление диапазонов. Тесты на `DELETE_RANGE` **не заменяют** проверку требуемого алгоритма split/join.

Если программа аварийно завершается, скрипт печатает первые 1200 символов stderr. Для полного отчёта санитайзера запустите проблемный вход вручную:

```bash
make sanitize
./avlset < tests/L10_bulk_delete.in
```

**Важно:** `make sanitize` должен действительно компилировать с `-fsanitize=address,undefined -fno-omit-frame-pointer -g`. В Linux/WSL доступна проверка утечек LeakSanitizer через ASan. На macOS возможности LeakSanitizer зависят от компилятора и окружения.
