# Публичные тесты для лабораторной работы `kvstore`

Это **открытый демонстрационный набор** для самостоятельной проверки программы на C.

В комплекте **59 тестов** по пяти уровням:

| Уровень | Число | Проверяемые возможности |
|---|---:|---|
| 4/10 | 8 | `SET`, `GET`, `DELETE`, `EXISTS`, `SIZE`, граничные длины |
| 6/10 | 7 | `LIST`, `PREFIX`, `RANGE`, `RENAME`, сортировка |
| 8/10 | 21 | чтение/запись `KVS1`, проверки ошибок, коды завершения, отсутствие частичного вывода |
| 9/10 | 11 | `--quoted`, `--comments`, `--ignore-case`, экранирование, ошибки |
| 10/10 | 12 | бинарный `KVB1`, загрузка/сохранение, повреждённые данные |

Это лишь примеры; **все тесты на оценку не публикуются**. Прохождение публичных тестов не гарантирует получения оценки. Публичный набор не предназначен для оценки асимптотики и не содержит максимальных нагрузок.

## Требования

- Python 3.10 или новее, дополнительные пакеты не требуются.
- Компилятор C для сборки вашей программы.
- Программа должна запускаться согласно условию, например `kvstore run commands.txt`.

## 1. Скомпилируйте свою программу

Пример для одного исходного файла (Linux/macOS):

```sh
cc -std=c17 -O2 -Wall -Wextra -Wpedantic -o kvstore main.c
```

Если проект состоит из нескольких файлов, соберите его привычным способом (например, `make`). В Windows имя исполняемого файла обычно будет `kvstore.exe`.

## 2. Запустите все тесты

Из каталога с тестами, Linux/macOS:

```sh
python3 tools/check.py /абсолютный/путь/к/kvstore
```

Или, если программа находится в соседнем каталоге:

```sh
python3 tools/check.py ../мой-проект/kvstore
```

Windows (PowerShell):

```powershell
py -3 tools/check.py "C:\path\to\kvstore.exe"
```

Путь к программе может содержать пробелы, тогда заключите его в кавычки.

## 3. Проверяйте группы отдельно

```sh
python3 tools/check.py ../мой-проект/kvstore --levels 4
python3 tools/check.py ../мой-проект/kvstore --levels 4 6
python3 tools/check.py ../мой-проект/kvstore --levels 8 9
```

Дополнительные возможности:

```sh
python3 tools/check.py ../мой-проект/kvstore --verbose
python3 tools/check.py ../мой-проект/kvstore --select rename
python3 tools/check.py ../мой-проект/kvstore --select 49
python3 tools/check.py ../мой-проект/kvstore --timeout 20
```

Тесты **строго сравнивают байты `stdout` и сохранённого файла**. В случае ошибки проверяются код завершения, пустой `stdout` и наличие диагностики в `stderr`. Точный текст диагностики не проверяется. Вывод программы и сохранённые файлы не должны содержать лишних пробелов или дополнительных строк.

## Как устроены тесты

Каждый тест находится в собственной папке внутри `tests/levelXX/`:

- `commands.txt` — входной файл команд (некоторые тесты специально проверяют его отсутствие);
- `input.store` — начальное состояние, если указано `--load`;
- `output.store` — заранее существующий файл, если необходимо проверить его сохранность при ошибке;
- `expected.stdout` — ожидаемый стандартный вывод (точное побайтовое совпадение);
- `expected.store` — ожидаемое состояние выходного файла, включая случаи, когда файл **не должен измениться**.

Имена тестов и аргументы запуска определены в `tests/manifest.json`.

**Не редактируйте тесты.** Скрипт запускает каждый тест во временной папке, поэтому исходные данные остаются неизменными.

## Разбор отдельного теста вручную

Например, тест `#049` находится в `tests/level08/case00049/`.

Чтобы разобраться в проблеме, откройте `commands.txt`, `input.store` и `expected.stdout`, затем вручную выполните программу на копиях этих файлов. Для выходных данных `--save` ожидаемый файл называется `expected.store`.

Текст условия продублирован в `docs/assignment.md`. Если преподаватель опубликует обновление условия, оно имеет приоритет перед копией из этого архива.

## Важные замечания

- В архив **не включены** эталонное решение, генератор преподавательских тестов и полный закрытый набор.
- Публичные тесты не проверяют отсутствие утечек памяти. Используйте AddressSanitizer и UndefinedBehaviorSanitizer самостоятельно в поддерживаемом окружении (на Windows удобнее через WSL).
- Если тест не прошёл, скрипт показывает номер, название, причину и, где возможно, небольшой фрагмент различий.
