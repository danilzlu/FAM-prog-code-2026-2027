# Лабораторная работа № 1 (пересдача): `kvstore`

## 1. Задача

Разработайте на языке C консольную утилиту `kvstore`, которая выполняет
команды над хранилищем строковых ключей и значений. Хранилище существует
в оперативной памяти во время работы программы; на высоких уровнях оно
также может загружаться из файла и сохраняться в файл.

**Работа выполняется индивидуально и самостоятельно. Генерация исходного
кода с помощью ChatGPT и других генеративных моделей недопустима.**

Уровни выполнения **4/10, 6/10, 8/10, 9/10, 10/10** вложены: для получения
оценки более высокого уровня необходимо реализовать все требования
предыдущих уровней.

Пользоваться деревьями или хеш-таблицами не требуется: достаточно динамических
массивов, структур, строк и алгоритмов поиска/сортировки.

## 2. Модель данных

Хранилище содержит не более одной записи для каждого ключа.

- Ключ — строка длиной 1–64 байта из ASCII. Первый символ — латинская буква,
  остальные — латинские буквы, цифры, `_`, `-`, `.`.
- По умолчанию ключи чувствительны к регистру: `Alice` и `alice` различаются.
- Значение — строка длиной 0–4096 **байтов**, без интерпретации в качестве
  числа. Допускаются печатные символы ASCII с кодами `0x20`–`0x7E`, а также
  байты TAB (`0x09`), LF (`0x0A`) и CR (`0x0D`). Нулевой байт запрещён.
- В базовом командном формате значение — непустой токен из байтов `0x21`–
  `0x7E`, кроме двойной кавычки и обратной косой черты. Остальные значения
  могут быть загружены из файла, а на уровне 9 — заданы в кавычках.

## 3. Запуск

```text
kvstore --help
kvstore run <commands> [--load <input>] [--save <output>] \
    [--quoted] [--comments] [--ignore-case] [--binary]
```

`--help` выводит краткую справку. `<commands>` — путь к командному файлу.
Если `--load` не указан, хранилище первоначально пусто. Параметр `--save`
сохраняет итоговое состояние **после успешного исполнения всех команд**.

Параметры указываются после файла команд в произвольном порядке. Дублировать
их нельзя. Неверные аргументы командной строки приводят к завершению с кодом 2.

## 4. Синтаксис командного файла

Используется ASCII с окончаниями строк только `LF` (`\n`). Последняя
строка может не оканчиваться `LF`. Длина одной физической строки не превышает
16 384 байта без окончания строки.

Одна команда занимает одну строку. Имя команды записывается ЗАГЛАВНЫМИ
буквами, аргументы отделяются пробелами и/или табуляциями. Пробелы и
табуляции в начале и конце строк игнорируются. Пустые строки игнорируются.
Лишние аргументы запрещены. В базовом формате значения не могут включать
пробелы, табуляцию, кавычки или обратную косую черту.

Команды исполняются **последовательно**:

| Команда | Эффект / результат |
|---|---|
| `SET key value` | Создаёт запись или заменяет значение, ничего не выводит |
| `GET key` | Выводит значение в двойных кавычках или `NOT_FOUND` |
| `DELETE key` | Удаляет запись, если она есть; ничего не выводит |
| `EXISTS key` | Выводит `true` либо `false` |
| `SIZE` | Выводит количество записей |
| `LIST` | Выводит все записи по возрастанию ключей |
| `PREFIX prefix` | Выводит записи, ключи которых начинаются с префикса |
| `RANGE left right` | Выводит записи в замкнутом лексикографическом диапазоне |
| `RENAME old new` | Переименовывает ключ, сохраняя значение |

Для `PREFIX` префикс должен удовлетворять тем же правилам, что и ключ.
Если `left > right`, результат `RANGE` пуст.

`RENAME` ничего не делает, если старый ключ отсутствует или оба ключа
совпадают. Если новый ключ уже существует, его прежнее значение заменяется
значением старого ключа, а старый удаляется.

`LIST`, `PREFIX` и `RANGE` выводят сначала строку `LIST N`, `PREFIX N`
или `RANGE N`, где `N` — число найденных записей. Затем выводятся записи
в формате `key "value"`, по одной на строку. Даже при нуле записей
заголовок обязателен.

Вывод строковых значений всегда заключён в двойные кавычки, даже если
входное значение было задано без кавычек. Специальные символы выводятся
через последовательности `\\`, `\"`, `\n`, `\r`, `\t`. Каждый результат
заканчивается символом `LF`.

Пример `commands.txt`:

```text
SET alice 100
SET bob 200
GET alice
SET alice 150
PREFIX a
DELETE bob
EXISTS bob
SIZE
```

Ожидаемый вывод:

```text
"100"
PREFIX 1
alice "150"
false
1
```

## 5. Файловый формат KVS1 (уровень 8/10)

Параметр `--load` загружает состояние из текстового файла `KVS1`,
`--save` сохраняет его в этот формат.

```text
KVS1
2
alice 5 68656C6C6F
empty 0 -
```

В первой строке размещена сигнатура `KVS1`, во второй — количество записей.
Каждая последующая строка имеет вид `KEY LENGTH HEX_VALUE`: три поля,
отделённые ровно одним пробелом. `LENGTH` — длина значения в байтах.
Каждый байт кодируется двумя шестнадцатеричными цифрами. Пустое значение
записывается как `0 -`.

Числа записываются без знака и ведущих нулей (кроме числа `0`).
При сохранении используются заглавные шестнадцатеричные цифры; при загрузке
также допускаются строчные. Все записи должны располагаться в строго
возрастающем лексикографическом порядке исходных ASCII-ключей. Все строки,
включая последнюю, должны заканчиваться `LF`. Дополнительные байты в конце
файла запрещены.

Необходимо проверять сигнатуру, формат и число записей, корректность
ключей и значений, длины, шестнадцатеричные цифры, сортировку и отсутствие
дубликатов. Одинаковый путь для `--load` и `--save` разрешён: сначала
полностью читается файл, затем обрабатываются команды, и только после этого
выполняется сохранение.

## 6. Дополнительные флаги (уровень 9/10)

- `--quoted` — разрешает кавычки у значений в `SET`, включая пустое
  `""`. Допустимые экранирования: `\"`, `\\`, `\n`, `\r`, `\t`.
  Неизвестные экранирования запрещены. Настоящий перевод строки внутри
  кавычек запрещён. Значения без кавычек по-прежнему разрешены.
- `--comments` — разрешает строки, первый непробельный символ которых `#`.
  Комментарии в конце обычных команд запрещены.
- `--ignore-case` — приводит ASCII-буквы всех ключей к нижнему регистру
  и сравнивает ключи без учёта регистра. При загрузке из файла сначала
  проверяется порядок исходных ключей, затем выполняется нормализация;
  возникновение дубликатов после нормализации — ошибка.

Все флаги должны корректно работать одновременно.

## 7. Бинарный формат KVB1 (уровень 10/10)

Параметр `--binary` переключает чтение и запись хранилища в двоичный
формат `KVB1`:

| Поле | Размер | Формат |
|---|---:|---|
| Сигнатура | 4 байта | ASCII `KVB1` |
| Количество записей | 4 байта | `uint32`, little-endian |
| Длина ключа | 1 байт | `uint8`, от 1 до 64 |
| Ключ | Переменный | ASCII |
| Длина значения | 4 байта | `uint32`, little-endian |
| Значение | Переменный | Исходные байты значения |

Последние четыре поля повторяются для каждой записи. Ключи идут в
лексикографическом порядке. Дублированные/неотсортированные ключи,
повреждённые поля и лишние байты после последней записи недопустимы.

Нельзя просто записывать структуры C в файл: порядок байтов и выравнивание
необходимо контролировать самостоятельно.

Для `GET` и `EXISTS` требуется не более `O(log n)` сравнений ключей.
Операции `SET`, `DELETE`, `RENAME` могут занимать `O(n)` времени.

## 8. Ошибки

Коды завершения:

- `0` — успех;
- `1` — ошибка данных, формата, файла или памяти;
- `2` — неправильный вызов командной строки.

Об ошибках сообщается только в `stderr`; точная формулировка не важна.
При любой ошибке `stdout` обязан оставаться пустым, даже если до неё
встречались команды, формирующие вывод. При ошибке загрузки или выполнения
команд файл `--save` не должен создаваться или изменяться. Если ошибка
возникает во время записи на диск, допускается частично записанный файл.

Начиная с уровня 8/10 необходимо обнаруживать неизвестные команды,
неверное количество аргументов, недопустимые ключи и значения,
повреждённые файлы и ошибки ввода-вывода и выделения памяти.

## 9. Уровни выполнения

| Уровень | Требуется |
|---|---|
| 4/10 | `--help`, `SET`, `GET`, `DELETE`, `EXISTS`, `SIZE`; корректные входные данные |
| 6/10 | Всё предыдущее + `LIST`, `PREFIX`, `RANGE`, `RENAME`; корректные входные данные |
| 8/10 | Всё предыдущее + `--load`, `--save`, KVS1, полная обработка ошибок |
| 9/10 | Всё предыдущее + `--quoted`, `--comments`, `--ignore-case` и их сочетания |
| 10/10 | Всё предыдущее + `--binary`, KVB1, эффективный поиск и большие наборы данных |

На уровнях 4/10 и 6/10 входные файлы и команды гарантированно корректны.
Начиная с уровня 8/10 проверяются также неправильные входные данные.

## 10. Ограничения тестов

| Максимум на один тест | 4/10 | 6/10 | 8–9/10 | 10/10 |
|---|---:|---:|---:|---:|
| Число команд | 5 000 | 12 000 | 25 000 | 200 000 |
| Записей одновременно | 2 000 | 5 000 | 8 000 | 100 000 |
| Сумма размеров ключей и значений | 2 МиБ | 4 МиБ | 16 МиБ | 32 МиБ |
| Размер стандартного вывода | 4 МиБ | 8 МиБ | 16 МиБ | 32 МиБ |

Для уровней 8–9 размер командного файла не превышает 16 МиБ, файла
`KVS1` — 40 МиБ. Для уровня 10 — соответственно 24 и 80 МиБ.

В больших нагрузочных тестах уровня 10 не более 2 000 команд изменяют
состояние; остальные команды только читают данные. Это позволяет использовать
отсортированные массивы и не требует хеш-таблиц.

Предварительные ограничения: **128 МиБ / 5 с** для уровней 4–9,
**256 МиБ / 10 с** для уровня 10. Время относится к одному запуску на
проверяющей машине и может быть откалибровано перед сдачей.

## 11. Требования к реализации

- Разрешается стандартная библиотека C; готовые библиотеки реализации
  key-value store использовать запрещено.
- Необходимо использовать динамическую память для данных неизвестного размера,
  проверять ошибки выделения и освобождать память при завершении и ошибках.
- Не допускаются утечки, обращения за границы и другие случаи неопределённого
  поведения. Массивы переменной длины (VLA) запрещены.
- Желательно разумное разделение на несколько `.c`/`.h`-модулей.
- Должна быть инструкция по сборке. Makefile рекомендуется, но не обязателен.
- Проверка проводится автоматическими тестами, анализом кода и защитой.

Реализация более высокого уровня должна проходить проверки всех нижних.
При оценивании учитываются также архитектура программы, качество обработки
памяти и способность объяснить принятые решения.
